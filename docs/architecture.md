# System Architecture Documentation

## Overview

The **Brand AI Readiness Audit** system follows a modular, evidence-first pipeline designed to assess web properties for AI discoverability, technical renderability, and machine readability.

The system decouples **General Evidence Extraction** from **Specialized Audit Skills**, ensuring that all page signals, structured data, resource links, image captions, and page role classifications are captured in a single pass into a unified **Shared Evidence Store** (`WebsiteEvidence`).

## Architectural Component Separation

To prevent hallucination, eliminate duplicate site crawls, and ensure reproducible audits, the architecture strictly segregates responsibilities across clear decoupled layers:

### 1. Discovery & Site Crawler
- **Responsibility:** Discover reachable pages, extract crawler rules, and fetch page HTML.
- **Components:**
  - `RobotsTxtParser`: Parses user-agent specific rules (`*`, `GPTBot`, `ClaudeBot`, `PerplexityBot`) and sitemap locations.
  - `SitemapParser`: Extracts child sitemaps and target URLs from sitemap indices and urlsets.
  - `PageRoleClassifier`: Categorizes URLs into functional roles (`homepage`, `about`, `contact`, `product`, `terms`, `documentation`).
  - `SiteCrawler`: Executes depth-bounded crawl using custom or default HTTP fetchers.

### 2. General Evidence Extraction Layer (`src/extraction/`)
- **Responsibility:** Ingest raw crawl manifests and convert observed facts into canonical, auditable `CanonicalEvidence` records with deterministic ordering, centralized Evidence IDs, and traceable provenance.
- **Strict Boundary:** The extraction layer strictly answers *"What exact evidence did we find?"*. It deliberately does **NOT** judge quality, compute scores, produce audit findings, decide AI readiness, generate recommendations, or query LLMs.
- **Canonical Evidence Schema (`src/shared/evidence_schema.py`):**
  - `id`: Centralized, sequential ID (`EV-00001`, `EV-00002`, ...) generated by `EvidenceIdGenerator`.
  - `type`: `EvidenceType` classification (e.g. `http_status`, `raw_html`, `heading`, `jsonld_raw`, `robots_rule`, `freshness_date`, `entity_name`, `link_item`, `image_item`, `crawl_coverage`).
  - `source`: High-level source type (e.g. `http_response`, `html_head`, `json_ld`, `robots_txt`).
  - `url`: Resource or page URL.
  - `timestamp`: ISO 8601 extraction timestamp.
  - `data`: Factual normalized data payload.
  - `provenance`: `Provenance` object (`source`, `extraction_method`, `url`, `location`, `selector`, `path`, `context`).
  - `is_raw`: Boolean flag distinguishing raw payloads (`raw_html`, `raw_robots`, `jsonld_raw`, `raw_headers`, etc.) from derived signals.
- **Modular Extractors:**
  - `ExtractionManager`: Master orchestrator coordinating extractors in a stable deterministic order, managing centralized ID generation, deduplication, and error resilience (`ExtractionResult`).
  - `HTTPExtractor`: Normalizes requested/final URLs, status codes, redirect hops, raw headers, and specific headers (`X-Robots-Tag`, `Last-Modified`, `Cache-Control`).
  - `TextExtractor`: Extracts structured text blocks (headings H1..H6 with level/index, paragraphs, lists, tables, blockquotes, captions) and text extractability signals.
  - `MetadataExtractor`: Owns document metadata, head title, description, canonical link, OpenGraph tags (`og:*`), Twitter cards (`twitter:*`), viewport, charset, and lang.
  - `SchemaExtractor`: Owns semantic structured data; extracts raw JSON-LD blocks, parsed JSON-LD objects, detected Schema.org `@type`s, and Microdata items.
  - `RobotsExtractor`: Extracts raw `/robots.txt`, parsed user-agent rules (targeting `GPTBot`, `ClaudeBot`, `PerplexityBot`, `Bytespider`, `Google-Extended`, `*`), crawl delays, and sitemap declarations.
  - `FreshnessExtractor`: Extracts publication and modification dates across HTTP `Last-Modified`, JSON-LD (`dateModified`, `datePublished`), Sitemap `<lastmod>`, and visible text, preserving both `raw_value` and ISO-normalized `normalized_value`.
  - `EntityExtractor`: Extracts factual entity identity data (organization name, address, phone, email, logo URL, `sameAs` links, Wikidata IDs).
  - `LinkExtractor`: Extracts HTML links (internal/external classification, `rel` attributes, anchor text) and downloadable document resources (PDF, DOCX, CSV).
  - `MediaExtractor`: Extracts image asset properties (dimensions, formats, alt text, captions, tracking heuristics) and interactive forms.
  - `ResourceExtractor`: Extracts special machine-readable endpoints (`/sitemap.xml`, `/llms.txt`, `/openapi.json`).
  - `SiteExtractor`: Extracts site-level crawl coverage, max depth, truncation reasons, resource summaries, and failed/skipped URLs.

### 3. Shared Evidence Store (`WebsiteEvidence`)
- **Responsibility:** Persist immutable, structured evidence models for the entire audited domain.
- **Key Models:**
  - `WebsiteEvidence`: Container for all `PageEvidence`, `RobotsEvidence`, and `SitemapEvidence`.
  - `PageEvidence`: Structured page snapshot containing metadata, headings, images, links, forms, documents, dates, and contacts.
  - `Provenance`: Standardized tracking of evidence source URL and DOM location context.

### 4. Semantic Understanding Adapter Layer
- **Responsibility:** Provide an extensible interface boundary (`SemanticUnderstandingAdapter`) for future optional LLM or vision semantic enrichment without creating hard dependencies in core audit skills.
- **Operations:**
  - Baseline `BaselineUnderstandingAdapter` provides deterministic fallbacks.
  - Pluggable adapter interface accepts `WebsiteEvidence` and returns enriched semantic insights.

### 5. Specialized Audit Skills
- **Responsibility:** Perform domain audits on top of `WebsiteEvidence`.
- **Skills:**
  - `crawl-render-audit`: Evaluates site crawlability, HTTP status, meta tags, heading hierarchy, content depth, and site coverage.
  - `structured-data-audit`: Evaluates JSON-LD presence, parse validity, schema types, entity completeness, and visible content consistency.

### 6. Scoring Engine & Report Generator
- **Responsibility:** Aggregate audit findings across all skills into a unified `AuditReport`.
- **Scoring Logic:**
  - Calculates percentage score (0–100) based on pass/fail/warning counts.
  - Enforces severity caps for critical failures (e.g. total AI bot block or fatal crawl errors).
